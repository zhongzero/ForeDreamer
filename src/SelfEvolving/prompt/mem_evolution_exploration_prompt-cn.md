探索目标：
- 为 data-process subagent 生成一个新的 MemGuide，并在需要时生成一个或多个新的 MemTool。
- 新 guide 必须形成一种与上面所有现有 guide 类别代表都明显不同的工作流模式。
- 不要只做表面修改，例如重命名工具或轻微改写 prompt。
- 差异应主要体现在工作流设计、任务拆解方式、推理结构或工具职责上。
- 默认把“明显不同”理解为：阶段数不同、状态转移不同、中间产物不同、工具角色分工不同，或信息在工作流中的流动方式不同。
- 如果新方案仍然只是“读取原始输入 -> LLM 直接处理 -> 写最终输出”的两阶段模式，那么它通常还不够新，除非你同时引入了与现有类别显著不同的工具职责或中间状态机制。
- 优先探索多阶段工作流，而不是最短路径工作流；在合适时，鼓励显式设计 3 个或更多阶段。
- 优先探索不同类型工具的组合，例如：抽取工具、结构化整理工具、中间文件写入工具、中间文件读取工具、片段合并工具、校验工具、最终写出工具。
- 强烈鼓励把关键中间结果保存在 `item_dir` 中，再由后续工具或 LLM 重新读取这些中间结果，形成更清晰的阶段边界。
- 不要通过复制已有 `read_*` / `write_*` 工具并只改少量文案、字段标题或返回字符串来伪装成新 workflow。
- 如果需要复用已有工具，复用的部分应只是新工作流中的一小部分；真正的创新应主要来自新的阶段结构、工具职责和中间状态设计。
- 只有在确实能支持一种明显不同的新 guide 类别时，才允许在返回的 MemGuide 中复用已有工具名。
- 如果一个真正新的工作流需要新工具，就创建新工具。

鼓励的探索方向示例：
- “原始输入读取 -> 结构化抽取并写中间 JSON/TXT -> 读取中间文件并生成压缩版 -> 再次读取压缩版并写最终输出”
- “原始内容切分 -> 分块提炼 -> 汇总中间笔记 -> 读取汇总笔记生成最终结果”
- “先抽取证据与元信息 -> 保存候选结论或检查清单 -> 再读取检查清单做校验/重写 -> 最终写出”
- “将‘读取/抽取/保存中间状态/重读中间状态/定稿写出’交给不同工具，而不是让一个读取工具承担全部前处理职责”
